# 2026-11-03 DSpark 窗口外 KV 回收适配

## 适配目的

让 DSpark draft 在只读取最近一段上下文的同时，归还窗口之外的旧 KV 块，供其他请求复用。target 继续保留自身需要的历史。

“回收”指释放请求对预分配 KV 池块的引用；共享块要等其他请求也释放引用后才可复用。因此，不能用 `npu-smi` 显存是否下降来判断回收是否生效。

本文与实现均位于分支 `030_dspark_ctxwin_tmp`，实现核对版本为 `74bc98bac`。
实现工作区：[/Users/wuyidong/.codex/worktrees/dspark-ctxwin-tmp/vllm-ascend](/Users/wuyidong/.codex/worktrees/dspark-ctxwin-tmp/vllm-ascend)。

## 核心做法

1. **读窗口**：按训练配置读取对齐后的上下文。起点为 `floor(max(anchor - W, 0) / align) × align`，终点包含当前 draft block；KV 写入仍使用绝对位置。
2. **独立回收**：draft 加载后，将其 paged attention 层的 KV spec 转为滑窗保留类型，让已有 `SlidingWindowManager` 回收旧块。只改这些 draft 实例的 spec，保留 FA4/FIA 的 attention mask 语义。
3. **保留安全余量**：调度保留量 `R = W + align + B + S + 1`，覆盖对齐、投机拒绝及长度截断余量。`W=2048、align=128、B=S=7` 时，`R=2191`。调度器按扣除在途步骤后的已处理 token 数，仅回收边界之前的完整块。
4. **检查分组**：draft 必须保留独立的滑窗策略；开启回收却被 planner 合并回 full-attention 保留策略时，直接报错。

## 使用方式

使用 MRv2 和已按窗口训练的 draft；其 `dflash_config` 需要同时包含 `context_window` 与 `context_window_align`。两项都缺失时不启用窗口适配，只配一项会报错；align 必须是 draft kernel block size 的整数倍。

在服务启动命令中设置：

```bash
--speculative-config '{"method":"dspark","model":"/实际路径/draft","num_speculative_tokens":7,"dspark_drop_outside_window_kv":true}'
```

- `true` 或省略：启用窗口外 KV 回收。
- `false`：保留读窗口，使用模型原有 KV spec；模型本身的 SWA、请求结束释放和一般缓存驱逐仍按原规则执行。
- APC 前缀缓存通过 `--enable-prefix-caching` 独立控制，可与两种回收配置组合；切换回收配置需要重启服务。

已有配置检查仍拒绝 PD KV connector、DCP/PCP 大于 1，以及关闭 hybrid KV manager 的组合。关闭回收不会放宽这些限制。
