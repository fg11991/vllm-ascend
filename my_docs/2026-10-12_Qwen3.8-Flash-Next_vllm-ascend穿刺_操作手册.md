### 为什么是这个组合

- **main 完全没有 qwen4_exp 实现**：只有一份部署文档（#17024），`envs.py` 的 QSA 变量 0 个、`hardware_profile.py` 的 QSA capability 0 个。必须叠 PR #16981。
- **PR #16981 merge 到最新 main 零冲突**，已验证。
- **版本配对天然成立**：#16981 复用上游 `vllm.models.qwen4_exp.amd`，该模块 vLLM v0.28.0 **无**、v0.29.0 起**有**；vllm-ascend main 自 #16527（09-23）起 pin `VLLM_TAG=v0.30.0`。PR 描述里"v0.28 不含该模块"的顾虑**已过时**。
- **不用官方 `qwen3.8-next-a3` 镜像**：它 2026-09-17 构建，当时 `VLLM_TAG=v0.28.0`，镜像内 vLLM **不含** Qwen4Exp，模型支持走"把上游代码拷进插件"的老路线（#15162/#15072），与 #16981 的"复用上游"架构**互斥**。

### 关键坑：官方文档的命令对本基线不适用

官方文档（`docs/source/tutorials/models/Qwen3.8-Flash-Next.md` 第 9 行）明确基于 **0.26.0rc**，而该 release 分支里 qwen4_exp 文件数为 **0** —— 那是另一套实现。照抄它的命令会连撞三个 KV 布局 bug。详见 [KV 布局三个 bug 定位](2026-10-12_Qwen3.8-Flash-Next_KV布局三个bug定位.md)。

必须偏离官方文档的三处：

| 参数 | 官方 | 本基线必须 | 原因 |
|---|---|---|---|
| `--block-size` | 不设 | **768** | six-region 要求 `block_size == max_ssm_bytes / k_token_bytes`，且 `% 128 == 0` |
| `--speculative-config` | 有（`qwen3_5_mtp`） | **先不开** | MTP 层 raw cache `head_size=140` ≠ 主模型层 128，必然触发 six-region page mismatch |
| graph | `FULL_DECODE_ONLY` | **`--enforce-eager`** | 无 MTP 的 graph 路径需上游 vllm#58040，未包含在 #16981 |

> 另外：官方文档的 `"method":"qwen3_5_mtp"` 对本模型是**错的**。`vllm/config/speculative.py:832` 把 `model_type` 从 `qwen4_exp` 映射为 `qwen4_exp_mtp`，而 `vllm_ascend/spec_decode/__init__.py:56` 认的正是 `qwen4_exp_mtp`。将来开 MTP 时用后者。

```bash
echo "=== 权重 ===" && ls -d /models/Qwen3.8-Flash-Next-w8a8-mtp && echo "=== 日志目录 ===" && mkdir -p /opt/w00958190/log && (touch /opt/w00958190/log/.t && echo "可写" && rm /opt/w00958190/log/.t) && echo "=== 代码树 ===" && git -C /vllm-workspace/vllm-ascend log -1 --format='%h %s' && echo "=== 真实可用核数 ===" && env -u OMP_NUM_THREADS -u OMP_THREAD_LIMIT nproc && python3 -c 'import os; print("sched_getaffinity:", len(os.sched_getaffinity(0)))'
```

> **`nproc` 陷阱**：`nproc` 会读 `OMP_NUM_THREADS` / `OMP_THREAD_LIMIT` 并以其为上限。本机设了 `OMP_NUM_THREADS=1`，裸跑 `nproc` 返回 1，但这**不是** CPU 限制 —— `sched_getaffinity` 是 640，cgroup 和亲和性从未受限。编译时必须 `env -u` 掉这两个变量。

## 3 零编译（不要编译自定义算子）

PR #16981 对 C++ 的改动**只有一处**：新算子 `qsa_expand_e3`（`torch_binding.cpp` 1 个 include + 1 个注册，`torch_binding_meta.cpp` 1 个 meta 函数 + 1 个注册）。别无其他 C++ 改动。

所以**镜像预编的 `vllm_ascend_C` 和 41 个算子已经够用**，只要 `VLLM_ASCEND_ENABLE_QSA_E3V=0`：

| `use_e3` | 走的实现 | 需要新算子 |
|---|---|---|
| `True` | `expand_qsa_block_indices_e3` | 是 |
| `False` | `expand_qsa_block_indices_npu` | 否 |

`use_e3` 只控制最后一步 block→token 索引展开；**Lightning Indexer 本体用 `torch.ops.npu.npu_lightning_indexer`（CANN 原生算子）**，不受影响。`envs.py` 里 `VLLM_ASCEND_ENABLE_QSA_E3V` 的**默认值本来就是 0**，`tests/ut/models/test_qwen4_exp_soc_gating.py:75` 有专门 UT 覆盖降级路径。

> 曾尝试完整编译（42 个算子）：第一次因 `OMP_NUM_THREADS=1` 把并行度压成 1，protobuf 单独编了 1277 秒后 ninja 失败，真实报错未取到。既然零编译可行且不影响数值，不再尝试。

## 6 已知问题与规避

| 问题 | 规避 |
|---|---|
| `block_size=400` 违反 `% 128` | `--block-size 768`（详见 bug 定位文档） |
| 算出 512，six-region 期望 768 | 同上 |
| MTP 层 raw cache `head_size=140` ≠ 主模型 128 → page mismatch | **不开 MTP**（抓 hidden 不需要） |
| 无 MTP 的 ACL Graph 崩溃 | `--enforce-eager`（需上游 vllm#58040，未包含在 #16981） |
| `qsa_expand_e3` 未编译 | `VLLM_ASCEND_ENABLE_QSA_E3V=0`，走 triton 展开，数值不变 |
| `nproc` 返回 1 | `OMP_NUM_THREADS` 作祟，见第 1 节 |
| decode 仅 2 token/s | eager + 无 MTP 的预期值；抓 hidden 不受影响 |
| Lightning Indexer 静默降级 | `_lightning_indexer_eligible` 硬条件：`query.shape[1] <= 64`、`head_dim == 128`、`compress_ratio == 4`、`token_topk == 2048`、cache shape `(192,1,128)`。不满足则**静默**退到 triton 选择器 |
| `--gpu-memory-utilization 0.95` | #15162 实测会导致 QSA cache 空间不足，**0.93 是验证值** |
| `VLLM_PLE_CPU_OFFLOAD` | **不要开**，上游 offload 传输是 CUDA-only |
| `/opt` 下有同事工作区 | `/opt/w00498770`、`/opt/t828158` 下的 `.so` 是 cpython-311，与本容器 Python 3.12 不匹配，勿误用、勿写入 |

## 7 后续步骤

### 第 2 步：给 Qwen4Exp 输出 aux hidden

改动位置：`vllm_ascend/models/qwen4_exp/model.py` 的 wrapper，必要时碰上游 `vllm.models.qwen4_exp.amd.model`。

- **aux id k（1≤k≤47）**：第 k 层 `attn_hyper_connection` 从 4 路残差读出的 2560 维向量（HF 对应 `layers[k].attn_hyper_connection(streams)[0]`），即送进第 k 层 attention 之前、已混合并归一化的输入
- **aux id 48**：`hyper_connection_mixer` 输出，即 `lm_head` 实际输入（本模型**无** final norm）
- `eagle_aux_hidden_state_layer_ids = [4, 16, 24, 36, 44, 48]`（SpecForge tap `[3,15,23,35,43]` + 1，再加 48）
- 每 token 存 6 × 2560；TP 下需拿到完整 2560 维
- **不要**抓 4×2560 原始残差，也不要抓 4 路相加/求平均
- 自检：在第 k 层内断言抓到的张量就是该层 attention 实际消费的输入（同一 tensor 或差为 0）；id 48 断言就是送进 `lm_head` 的张量

### 第 3 步：`extract_hidden_states` 落盘

- 通路已存在：`vllm_ascend/spec_decode/extract_hidden_states_proposer.py`（镜像内已确认存在），且 `patch/platform/patch_mamba_config.py:163` 已为混合模型放行 `extract_hidden_states` 方法
- 请求走 `/v1/completions`，`prompt=[token ids]`、`max_tokens=1`、`return_token_ids=true`，**不让服务端渲染 chat template**（loss mask 由 SpecForge 按自己的渲染算，token 必须一一对应）
- 需关闭 chunked prefill 和 prefix caching —— **注意**：关掉 prefix caching 会使 `mamba_cache_mode` 变 `none`、`mamba_block_size = max_model_len`，block_size 会被重算。`--block-size 768` 到时仍是关键
- **必须 eager**：ACL Graph 会 padding batch，而 vllm#58040 要修的正是「QSA mapped-token count 在 graph padding 下未 clamp」，无法保证抓到的 hidden 与 eager 逐位一致

### 暂缓项

**原生 MTP 基线（k=3/k=4）** 阻塞于 bug #3。它是给下一阶段草稿模型做对照用的，不阻塞抓 hidden。待 six-region 的 fallback 补丁验证通过或上游修复后再补。
