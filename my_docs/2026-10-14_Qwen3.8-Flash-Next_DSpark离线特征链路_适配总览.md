# Qwen3.8-Flash-Next DSpark 离线特征链路：vLLM-Ascend 适配总览

## 摘要

> DSpark 草稿模型需要 Qwen3.8-Flash-Next 的 auxiliary hidden states 作为离线训练特征。原方案用 Transformers 参考实现抓取，慢到抓不出可用数据量；改用 vLLM-Ascend 抓取后，同一个引擎、同一份 W8A8 权重既供特征抓取也供后续投机评测，训推天然一致。
>
> **当前状态：整条链路已打通并跑完一轮冒烟。** A3 单机 TP8 起服务 → 抓取 100 条 pilot 特征 → 转换 → DSpark 草稿训练，**loss 正常下降、grad norm 有限**。
>
> 代价与边界：**放弃原生 MTP**（MTP 层的 QSA raw cache 宽度与主模型层不同，触发 six-region 一致性检查），**必须 eager**，**样本上限 2304 token**。为打通链路修了 **7 个 bug**，全部出自两个未合入 PR（#16981 与它继承的 #17144）的交互面，且有一个清晰共性：`extract_hidden_states` 是唯一会设 `kv_transfer_config` 的场景，于是把 vllm-ascend 里多处「有 KV transfer 就走保守路径」的假设逐个踩了一遍。
>
> 本文是端到端总览。基线选型的完整论证见[《服务拉起与基线选型》](2026-10-12_Qwen3.8-Flash-Next_vllm-ascend_服务拉起与基线选型.md)，aux hidden 接口与逐 bug 定位见[《hidden 抓取适配与 debug》](2026-10-12_Qwen3.8-Flash-Next_hidden抓取适配与debug.md)，操作步骤见[《分步操作指南》](2026-10-13_hidden抓取_分步操作指南.md)。原生 MTP 基线与草稿接受率评测**不在本文范围**。

## 1 背景与目标

### 1.1 为什么要在 vLLM-Ascend 上抓

DSpark 草稿模型由 SpecForge（`fg11991/specforge` 分支 `1008_next_flash`）训练，训练读离线特征。特征原计划用 Transformers 参考实现抓取，但其 QSA 索引实现对每个 query 走一次 Python 循环（每个稀疏层 `seq_len` 次 host 同步），4k token 的抓取不现实。

改用 vLLM-Ascend 的收益不只是速度：**同一个引擎、同一份 W8A8 权重既抓训练特征又做投机推理评测**，消除了训练特征与 serving 行为之间的口径漂移 —— 这正是 DeepSeek-V4 那次掉点的根源（训练与 serving 的锚点差了一位，静默吃掉接受率）。

### 1.2 核心挑战

1. **基线不存在**：vllm-ascend main 有部署文档但**没有实现**（`vllm_ascend/models/qwen4_exp/` 0 个文件，QSA 相关 env 与 capability 均为 0）；支持分散在 6 个以上未合入 PR 中，彼此不兼容。
2. **上游没有 aux hidden 接口**：上游 Qwen4Exp 只实现 MTP，`SupportsEagle3` / `aux_hidden_state` 在 `vllm/models/qwen4_exp/` 下 grep 为空。
3. **口径必须逐位同义**：训练侧实现即标准答案，serving 侧每一处计算都要对得上。而两个框架在同一语义位置的 tuple 索引**是反的**（见 3.2）。
4. **两个未合入 PR 的交互面无人覆盖**：#16981 验证的是 MTP 场景，`extract_hidden_states` 带来的 `kv_transfer_config` 和 cache-only 层从未与 six-region 一起跑过。

## 2 端到端链路与配方

### 2.1 数据流

```
语料
 └─ SpecForge: 渲染 chat template（开思考 / reasoning_effort=xhigh / 保留历史 reasoning）
     └─ token ids + loss_mask
         └─ vLLM-Ascend 抓取服务  POST /v1/completions
            prompt=[ids], max_tokens=1, return_token_ids=true      ← 服务端不渲染
             └─ ExampleHiddenStatesConnector 落盘
                {req_id}.safetensors : hidden_states [T, 6, 2560] bf16 + token_ids [T]
                 └─ SpecForge 转换
                    前 5 个 tap → hidden_states [1, T, 12800]
                    第 6 个     → target_last_hidden_states [1, T, 2560]
                     └─ .ckpt（+ input_ids [T] + loss_mask [T]，四者 T 相等）
                         └─ DSpark 草稿训练
```

**为什么直接发 token id**：loss mask 由 SpecForge 按自己的渲染计算，token 必须一一对应。让服务端再渲染一次 chat template 就无法保证一致。

### 2.3 零编译

PR #16981 对 C++ 的改动**只有一处**：新算子 `qsa_expand_e3`（`torch_binding.cpp` 1 个 include + 1 个注册，`torch_binding_meta.cpp` 1 个 meta + 1 个注册）。因此镜像预编的 `vllm_ascend_C` 与 41 个算子已足够，只要 `VLLM_ASCEND_ENABLE_QSA_E3V=0`。

三条支撑证据：该 env 的**默认值本来就是 0**；`tests/ut/models/test_qwen4_exp_soc_gating.py:75` 有 UT 覆盖降级路径；`use_e3` 只控制最后一步 block→token 索引展开，而 **Lightning Indexer 本体用 CANN 原生的 `torch.ops.npu.npu_lightning_indexer`**，不受影响。

> 曾尝试完整编译 42 个算子：首次因 `OMP_NUM_THREADS=1` 把并行度压成 1，第三方 protobuf 单独编了 **1277 秒**后 ninja 失败。既然零编译可行且不影响数值，未再尝试。

### 2.4 抓取服务配置

启动命令完整版见操作手册，这里只列**必须偏离官方文档**的部分及其代码依据：

| 参数 | 官方 | 本链路 | 依据 |
|---|---|---|---|
| `--block-size` | 不设 | **768** | six-region 要求 `block_size == max_ssm_bytes / k_token_bytes`（`six_region_kv_cache_layout.py:231`）且 `% 128 == 0`（`patch_kv_cache_utils.py:769`） |
| `--speculative-config` | MTP k=3 | **extract_hidden_states** | 抓取方法；MTP 另有阻塞，见 3.3 |
| graph | `FULL_DECODE_ONLY` | **`--enforce-eager`** | 无 MTP 的 graph 路径需上游 vllm#58040（未包含在 #16981） |
| `--enable-prefix-caching` | 开 | **关** | 命中缓存的 token 不重新 forward，其 aux hidden 根本不会生成，落盘 T 对不上 |
| `--enable-chunked-prefill` | 开 | **关** | 保守选择：speculators 无条件关闭；GDN 递归 state 与 PLE n-gram 在 chunk 边界的行为未逐行验证 |
| `--max-model-len` | 135168 | **2304** | 受 3.4 的显存放大链所限 |

注意 `enable_prefix_caching` 在 vLLM 中**默认为 `True`**（`config/cache.py:130`），必须显式 `--no-enable-prefix-caching`，否则 `mamba_cache_mode` 被自动设为 `align`，与关闭 chunked prefill 冲突（`models/config.py:641` 的 assert）。

## 3 关键问题与解决

### 3.0 总览

| # | 现象 | 根因 | 处置 | 状态 |
|---|---|---|---|---|
| 1 | `block_size=400 violates kernel/compression alignment (ratio=4)` | 实际违反 128 对齐；报错只打印 `ratio` | `--block-size 768` | ✅ |
| 2 | `block_size=512 was not aligned; expected 768` | vLLM 按 K+V/token 推导，PR 按仅 K 推导，差约 2 倍 | 同上 | ✅ |
| 3 | `raw_key_cache page mismatch: view=2048, region=2240` | MTP 层 raw cache `head_size=140` ≠ 主模型 128；layout 取 owner max、runner 算单层 | 不开 MTP | ✅ 绕过 |
| 4 | `Qwen4Exp speculative decoding supports only its native MTP checkpoint...` | 上游白名单 `{mtp, ngram, ngram_gpu}` | patch：调用上游时临时摘掉 `speculative_config` | ✅ |
| 5 | 4608 token 需 20.6 GiB，预算仅 11.83 GiB | 预算豁免要求 `kv_transfer_config is None` | **先改错一次后撤销**，改用更短 `max-model-len` | ⚠️ 规避 |
| 6 | 同上的放大机制 | `CircularBufferSpec` 的 ring 容量污染 token-indexed gcd，hidden cache block_size 塌到 8 | 实现修正但**默认关闭** | ⚠️ 规避 |
| 7 | `QSAStateBackend has no attribute get_kv_cache_shape` | 同样的 `kv_transfer_config is None` 条件让 six-region **布局**被整体丢弃 | 对 extract_hidden_states 放行该条件 | ✅ |

**共性**：`extract_hidden_states` 是唯一会设 `kv_transfer_config` 的场景。vllm-ascend 在至少三处用「有 KV transfer 就走保守路径」这个假设（预算缩放、six-region 布局选择、shared backing），而 `ExampleHiddenStatesConnector` **只写那个专用的 hidden-state cache-only 层、不迁移任何 attention / Mamba 块**，这个假设对它全都不成立。`patch_mamba_config.py:155-161` 其实已经为同一个 connector 写明了这条理由 —— 只是没有推广到另外两处。

下面展开三个最有价值的。

### 3.1 索引陷阱（本次最重要的发现）

两个框架在同一语义位置的 tuple 索引**是反的**：

| | HF / SpecForge | vLLM `GatedResidual.mix()` |
|---|---|---|
| 门控读出（单流 2560，**要抓这个**） | `[0]` | **`[1]`** = `block_input` |
| 4 路残差 10240（**绝不能抓**） | 不在返回值里 | **`[0]`** = `hidden_states` 原样透传 |

**证据**。训练侧断言写死（`tests/test_offline_capture/test_hf_qwen4_exp.py:198-203`）：输入 `streams.shape[-1] == 4 * 64`，输出 `sink.shape == (1, 30, 64)` —— `[0]` 是单流。serving 侧（`hyperconnection.py:150`）：`return hidden_states, block_input, injection`。

**为什么后果是静默的**：若误取 `mix()[0]`，落盘的是 `hc_count × hidden_size = 10240` 维原始残差，而训练读取端 `_normalize_hidden_states` 遇到 4 维 hidden **按流求平均**（那是 DSV4 口径）而非拒绝 —— 训练照常进行，接受率被悄悄吃掉。与 DeepSeek-V4 锚点偏移同一类失败模式。

**三重防护**：索引写成命名常量 `_BLOCK_INPUT_INDEX = 1` 并在 docstring 解释；每次抓取校验 `readout.shape[-1] == hidden_size` 否则抛错（同时覆盖 TP 分片）；单测直接断言捕获宽度是 `hidden_size` 而非 `hc_count * hidden_size`。

### 3.2 编号约定与「加 1」的核实

两侧编号差 1，方向容易搞反：

| | 语义 | 本模型取值 |
|---|---|---|
| SpecForge `target_layer_ids` | 第 i 层的**输出** | `[3, 15, 23, 35, 43]` |
| vLLM aux id | 第 k 层的**输入**（id 0 是 embedding） | `[4, 16, 24, 36, 44]` |

aux id 48（`= num_hidden_layers`）指最后一层之后，即 `hyper_connection_mixer` 输出 —— 本模型**无 final norm**，所以它直接就是 `Qwen4ExpModel.forward` 的返回值、也是 `lm_head` 的输入。

**加 1 发生在哪里（已核实）**：`vllm_ascend/worker/model_runner_v1.py:883-898` 覆写了 `_get_eagle3_aux_layers_from_config`，但它**先调 `super()`**（上游读 `eagle_aux_hidden_state_layer_ids`，**原样返回不加 1**），仅当上游返回空且 `use_dspark()` 为真时才对 `target_layer_ids` 加 1。所以抓取阶段手写 `[4,16,24,36,44,48]` 正确、不会加两次；阶段二草稿 config 保持 `[3,15,23,35,43]` 也正确。speculators 的 `include_last_layer` 追加的是 `num_hidden_layers`（48 而非 47），独立印证了 id 48 的语义。

### 3.3 MTP 与 six-region 不兼容（已确认，非配置错误）

DIAG 实测全部 13 个 `qsa_raw` owner：

| owner | block_size | num_states | **head_size** | real page |
|---|---|---|---|---|
| `layers.3/7/…/47`（12 个） | 8 | 8 | **128** | **2048** |
| **`mtp.layers.48`** | 8 | 8 | **140** | **2240** |

`qsa_compressed` 的 13 个 owner（含 MTP）全部 `head_size=128`，完全一致 —— 差异只在 raw、只在 `head_size`。

`head_size=140` 是**上游设计**：`qsa_cache.py:853` 的 `CircularBufferSpec(head_size=self.head_size, ...)`，该值由 `QSARawKeyCache` 实例持有；同一 MTP 层的 compressed cache 仍是 128，说明 raw 与 compressed 是两个独立 cache 类，维度本可不同。**改不得。**

而 `six_region:275` 取**全部 owner 的 max**（2240），`model_runner_v1:5945` 算**单层**（2048），两者 `!=` 比较。这个校验**也放宽不得**：`make_contiguous_slab_view` 创建的是连续 view、没有 per-block stride，若 region 按 2240/block 分配而 view 按 2048/block 连续读，**每个 block 错位 192 字节**。

**结论：six-region 的「同角色 owner 共享一个 page size」假设，对带 MTP 的 Qwen4Exp 从来不成立。** 这与 PR 描述中「Real A3 W8A8 TP8/DP1 single-request runs with MTP=3 ... produced normal output」矛盾，除非那次验证用的是 six-region 合入之前的树。

**处置：不开 MTP**。这同时消除两件事 —— 那个 140 宽的 owner 消失（13 → 12，全部 128），且 ring capacity 从 8 降到 4（`qsa_cache.py:848` 的 `span = compress_ratio + num_speculative_tokens`）。抓取本就不需要 MTP（`max_tokens=1` 纯 prefill）。

### 3.4 显存：一次改错与一条放大链

**这是本次唯一一处我改错并撤销的改动，值得记下过程。**

`worker.py:703` 有个豁免为 Qwen4Exp 这类打包布局保留全额预算，其条件含 `kv_transfer_config is None`，capture 因有 connector 被排除，预算按 0.4865 缩放到 11.83 GiB。我据注释「compressed QSA descriptor 是同一块 page-strided backing 的逻辑视图」判断该排除不成立，遂放宽 —— 结果**分配阶段 OOM**，且降 `gpu-memory-utilization` 反而更差（0.93 差 69 MiB，0.90 差 228 MiB）。

**为什么错**：`kv_cache_utils.py:2296-2307` 先把 `HiddenStateCacheSpec` 从 packed spec 剔除、再作为**独立 group** append。capture 确实携带一份 packed 分配之外的 page，「所有 group 共享一块 packed backing」的前提不成立；`utilization` 调不动是因为超额是结构性的。**教训：只读了豁免的注释就采信其前提，没核查 hidden cache 是否真在 packed backing 里。**

真正的放大链（实测两点线性吻合：`8192 → 37.47 GiB`、`6144 → 28.14 GiB`，即 **4.576 MiB/token**）：

| 环节 | 值 | 来源 |
|---|---|---|
| `num_speculative_tokens` | **1**（硬性） | `extract_hidden_states.py:35` 的 `assert` |
| QSA ring capacity | **8** | `qsa_cache.py:848` |
| `gcd(768, 8, 4608)` | **8** | `kv_cache_utils.py:2325` |
| hidden cache block_size | **8** | 同上 |
| block 数（4608 token） | **576** | 由最小 block_size 决定 |
| 每 block 代价 | **36.6 MiB**（six-region 占 35.85，hidden cache 仅 0.75） | — |

**浪费的本质**：six-region 实际只需 `4608/768 = 6` 个 block，却被分配 576 个 —— **96 倍**，因为所有 group 共享同一 block 索引空间，而 hidden cache 的 `block_size=8` 把 block 数定死了。

`CircularBufferSpec` 本不该参与这个 gcd：它的 `block_size` 是环中存几行 key，而 `max_num_blocks_per_req()` 返回 **1**（`kv_cache_interface.py:884`，注释 "The ring occupies one block per request for its whole lifetime"）—— 它从不按 token 索引 block。排除后 `gcd = 768`，block_size 变 24，block 数降到 192，page 浪费从 68.75% 降到 6.25%。

**但该修正未在真机验证，且风险静默**：无法证明不同 block_size 的 group 可安全共存于同一 block-id 空间（block manager 路径未逐行走完），推断错误会导致 `slot_mapping` 偏移、抓到错数据而不报错。因此**关在 `VLLM_ASCEND_QWEN4EXP_WIDEN_HIDDEN_CACHE_BLOCKS` 后面，默认 0**，env 注释写明启用前必须通过的逐位对比。

**实际采用的方案**：用更短的 `max-model-len`。验证训练有效性只需约 200 条样本，序列长度并非硬要求 —— 上游原始行为在缩放预算下可服务约 2544 token，`2304`（= 768×3）即可，**零代码改动、零静默风险**。

> **工程判断的归属**：这个取舍是用户提出的。我连着两轮在为「支持 4096」改显存，而那个长度只是初版需求里的样本上限，与本阶段「验证训练有效性」的目标无关。退一步问「这个功能我们到底需不需要」比继续修更有效。

### 3.5 aux hidden 接口实现

上游完全没有这套接口，在 Ascend wrapper 里补齐，**不改上游、不改任何计算**。

| aux id | 对象 | 成本 |
|---|---|---|
| **48** | `Qwen4ExpModel.forward` 的返回值 | **零改动** |
| **4,16,24,36,44** | `block_input`，层 forward 的**局部变量** | per-instance 包装该层 `attn_hyper_connection` 的 `mix`/`combine_and_mix`，只读返回值 |

选择 per-instance 包装而非重写层 forward：改动最小、不复制上游逻辑；`attn_hyper_connection` 是每层独立的 `GatedResidual` 实例，只包装 5 层，`mlp_hyper_connection` 与其他层完全不碰。forward hook 不可行（拿不到局部变量）。

一个需避开的坑：`EagleModelMixin._maybe_add_hidden_state()` 的默认语义是 `hidden_states + residual`（标准 pre-norm 残差相加），**不能用** —— 口径要求不对 4 路做任何相加或平均。

**自检**（`VLLM_ASCEND_QWEN4EXP_AUX_HIDDEN_SELF_CHECK`，默认 0）：对 aux id k，额外包装该层 attention 的 forward，断言 `consumed is captured`（**对象同一性**，比「差为 0」更强）；对 id 48，断言返回列表里 mixer 那一槽 `is` backbone 的返回值。

**Review 修复的三项**：

| 级别 | 问题 | 根因 |
|---|---|---|
| P1 | forward 改成 `*args` 后动态维度标记全失效 | 上游 `_mark_dynamic_inputs` **按参数名**定位张量 |
| P2 | 开启 self-check 后**正常请求**也抛异常 | 原实现在 logits 头断言输入是完整 backbone 输出，但 runner 传的是 `hidden_states[logits_indices]`，索引必然产生新对象 |
| P1 | PP>1 不兼容 | 本 rank 外的层是 `PPMissingLayer`；且 `patch_eagle3_pp_aux_propagation` 以 `EagleModelMixin` 为判据会**替换** forward，丢掉整条 hyper-connection |

## 4 结果

### 4.1 服务

| 项 | 结果 | 口径 |

### 4.3 训练冒烟

**通过。** 100 条 pilot 特征，DSpark 草稿训练：**loss 正常下降、grad norm 有限**。

配置（相对 `examples/configs/qwen3.8-flash-next-dspark-offline-npu.yaml`）：

| 覆盖 | 默认 | 冒烟值 | 理由 |
|---|---|---|---|
| `training.accumulation_steps` | 64 | **1** | **关键**：默认 global batch = 1×64×8 = 512 > 100 条，一个 optimizer step 都走不完 |

## 5 当前边界

- **仅 Atlas 800 A3 + TP8 + 该份 W8A8 权重**。A2 未验证；官方文档声明 A2 与 950 系列暂不支持。
- **必须无 MTP + eager**。MTP 阻塞于 3.3；无 MTP 的 ACL Graph 需上游 vllm#58040。
- **必须关 prefix caching 与 chunked prefill**。前者会使命中缓存的 token 不重新 forward、aux hidden 缺失（**必然破坏**）；后者是保守选择（未验证等价性）。
- **样本上限 2304 token**。放宽需启用默认关闭的开关，且必须先做逐位对比。
- **PP = 1**。aux hidden 接口显式拒绝 PP>1。
- 基线依赖两个 OPEN PR（#16981 与它继承的 #17144），两者都可能变动。
- `chat_template.jinja` 中控制「保留历史 reasoning」的变量名**仍未确认** —— serving 侧不需要（直接发 token id），但训练侧生成 token id 时需要，且 `resolve_chat_template_kwargs` 会**静默丢弃**不认识的变量。

## 6 总结与展望

### 已证实

1. **链路打通**：A3 TP8 服务 → 100 条特征抓取 → 转换 → DSpark 训练冒烟（loss、grad 正常）。
2. **可用基线**是 nightly-main-a3-openeuler 镜像 + main `ea01a44ba` + PR #16981 `c6d9e38f8`，且**零编译**即可（PR 的 C++ 改动仅 1 处新算子）。
3. **官方镜像与官方文档命令均不可用**，原因是架构互斥与版本错配，非配置问题。
4. **aux hidden 接口已实现**，与 SpecForge 五项逐项对齐，纯读取不改计算，42 个单测。
5. **索引陷阱已定位并三重防护** —— HF 的 `[0]` 对应 vLLM 的 `[1]`，误取会静默掉点。
6. **MTP 与 six-region 不兼容是真实结论**，非配置错误。
7. 7 个 bug 有清晰共性：`extract_hidden_states` 的 `kv_transfer_config` 踩遍了多处保守假设。
